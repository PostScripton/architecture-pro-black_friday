# Мобильный мир - отказоустойчивость MongoDB (задания 1-6)

Проектная работа по архитектуре. Цель - повысить отказоустойчивость и
пропускную способность взаимодействия `pymongo-api` с MongoDB для онлайн-магазина
"Мобильный мир". Исходный кейс описан в `project_overview.md`.

## Архитектура: варианты схемы

Подготовлено пять вариантов, каждый дорабатывает предыдущий:

1. Шардирование (2 шарда).
2. Репликация (replica set по 3 узла на каждый шард).
3. Кеширование (Redis).
4. Горизонтальное масштабирование (API Gateway + Consul).
5. CDN (раздача статики по регионам).

Итоговая схема со всеми вариантами (задания 1, 5, 6):
[`tasks/task_6/task6_5_cdn.drawio`](tasks/task_6/task6_5_cdn.drawio).

Пояснения к схемам: [`tasks/task_1/solution.md`](tasks/task_1/solution.md),
[`tasks/task_5/solution.md`](tasks/task_5/solution.md),
[`tasks/task_6/solution.md`](tasks/task_6/solution.md).

## Директории с реализацией MongoDB

- `mongo-sharding` - шардирование (задание 2).
- `mongo-sharding-repl` - шардирование + репликация (задание 3).
- `sharding-repl-cache` - финальная реализация (задания 2, 3, 4): шардирование +
  репликация + Redis. Эта директория используется для проверки.

## Как поднять стенд

Финальный стенд - в директории `sharding-repl-cache`. Он содержит приложение
`kazhem/pymongo_api:1.0.0`, `redis` и MongoDB с шардированием и репликацией.

```bash
cd sharding-repl-cache
docker compose up -d
chmod +x init.sh
./init.sh
```

Скрипт `init.sh` инициализирует config server, реплика сеты обоих шардов,
добавляет шарды в кластер, включает шардирование и наполняет базу (>= 1000
документов). Ручные шаги и команды проверки подробно описаны в
[`sharding-repl-cache/README.md`](sharding-repl-cache/README.md).

## Как проверить

Проверить статус сервисов:

```bash
docker compose ps
```

Откройте приложение в браузере:

- локально: http://localhost:8080
- на виртуальной машине: узнайте белый ip (`curl --silent http://ifconfig.me`) и
  откройте http://<ip>:8080

Приложение отдаёт JSON с информацией о MongoDB (общее количество документов,
распределение по шардам, число реплик) и статусом использования кеша.

Кеширование проверяется на эндпоинте `/<collection_name>/users`: второй и
последующие вызовы выполняются менее чем за 100 мс. Команды проверки репликации и
распределения по шардам - в [`sharding-repl-cache/README.md`](sharding-repl-cache/README.md).
